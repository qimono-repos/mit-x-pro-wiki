## Hard rules
- **The repo is public: no quiz answers anywhere in it** (pages, hints, logs, commit messages). Hints give the method, never the result. Answers live in the private Anki kit (`qcfx2-anki-kit/`, kept *outside* this repo, next to it).
- Cite claims with links to `mit-raw/` lines or source notes. Mark anything not from the course as *Background* or *own reasoning*.
- When the course contradicts itself or is wrong (it happens: BCH sign, V_nc/V_ne, u as eigenvalue vs eigenvector), record it on the concept page and in the log. Don't silently fix it.
- Obsidian block refs: the `^id` goes at the end of a line (its own line after math or lists).
- In Python that writes LaTeX, use raw strings (`r"..."`): `\n`, `\t`, `\f` inside `\neq`, `\to`, `\text`, `\frac` have already broken pages once.

## Quiz workflow (the "5-point drill")
For each eDX question: (1) does it match our record (raw line + concept links)? (2) the answer, (3) a reason for **every** option, (4) the course reference, (5) any knowledge gap, and if there is one, add an external source. After Albert reports a grade: add it to `GRADED`, paste the course explanation into `EXPL` (Anki only), rebuild with the kit, commit the regenerated `wiki/quizzes/` pages, push.

What we learned about this course's questions: true options are near-verbatim lecture lines. False ones carry absolutes ("always", "only", "proven", "infinite") or a single dropped term. Explanations, when shown, address only the false options.
